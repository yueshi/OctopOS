# 复盘项目报告

目标：用台账里的真实行回答“这周怎么样、哪里卡住、谁要决策”。只读，不修改任何行。

## 步骤

1. **找到应用**：`app_list`，找到「项目报告台账」，记下 `app_id`。

2. **确定最新报告期**：

   ```text
   app_read_data(app_id=<app_id>, table="period_reports", limit=500)
   ```

   取 `period` 最大的一行。如果没有导入记录，直接告诉用户“还没有导入报告”。

3. **读取本期任务**：

   ```text
   app_read_data(app_id=<app_id>, table="main", limit=500, offset=<total-500>)
   ```

   先用返回的 `total` 估算最后一页；任务按报告期/项目/任务编号排序，最新一期的行在末尾。
   如果 500 行里跨了多个报告期，只保留 `period == 最新报告期` 的行；需要更多就往前翻页。

4. **汇总**：

   - 任务数、已完成、进行中、阻塞、未开始；
   - 完成率 = 已完成 / 任务数；
   - 延期数（`health == "delayed"` 或 `days_late > 0`）；
   - 有风险数（`health == "at_risk"`）；
   - 按项目分组的任务数、完成率、延期数、阻塞数；
   - 高优先级且未完成的任务（`priority == "high"` 且 `status != "done"`）；
   - 连续报告期都延期或阻塞的任务（如果用户问趋势，再按 `task_id` 跨期比较）。

5. **输出**：

   ```text
   **2026-W46 项目报告复盘**

   总体：12 个项目、186 条任务；完成 98 条（52.7%），进行中 61，阻塞 9，未开始 18；延期 14，有风险 11。

   | 项目 | 任务 | 完成率 | 延期 | 阻塞 |
   | --- | ---: | ---: | ---: | ---: |
   | A 项目 | 42 | 61% | 3 | 2 |
   | B 项目 | 35 | 40% | 7 | 4 |

   需要决策：
   - A 项目「接口联调」阻塞 6 天，负责人待确认；
   - B 项目连续两周延期，建议确认资源或缩小范围。
   ```

   数字必须来自读到的行；缺字段就写“未提供”，不补造。

6. **建议**：只给与数据直接相关的下一步，例如“补负责人”“确认范围”“把延期任务拆小”。不要把复盘变成泛泛的管理建议。

## 边界

- 不写数据；需要修正状态时，让用户改源 Excel 后重导该报告期。
- 不删除、不更新任务行。
- 不跨应用比较；如果用户要跨部门对比，先说明当前台账的范围。
- 不把“未上报”当成“已完成”或“已取消”。
- 不编造趋势；没有前几期数据就说“暂无对比数据”。

## 失败处理

| 现象 | 处理 |
| --- | --- |
| 没有 `period_reports` 表 | 应用未初始化完整；先跑 `pm-report-init` |
| 读不到任务 | 确认 `app_id` 和当前用户权限 |
| 本期行超过 500 | 分页读取，按 `period` 过滤；不要只取第一页就下结论 |
| 字段为空 | 在输出里标“未提供”，不要用 0 代替缺失 |
