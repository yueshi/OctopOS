02 Product / 边界

先说清楚它做什么、不做什么

知道边界，后面看功能时更容易判断是否适合自己的场景。

它是什么

做什么
  • 一个多用户的数据应用：表、行和带权限的页面，数据存在控制面数据库。
  • 一个 Agent 交付物：Agent 可以建表、改字段、写页面，再把数据读回来。
  • 可以协作：所有者、管理员、协作者和访问申请。
  • 可以分享：只读公开链接、发布快照、PII 脱敏、随时撤销。
  • 可以接数据：数据源、只读服务、Webhook 和定时任务。
  • 可以维护：备份恢复、行历史、页面回滚和审计。

它不是什么

不做什么
  • 不是 ERP / CRM 的权威库：核心交易仍应留在原系统。
  • 不是 BPM 或工作流引擎：没有任意流程编排。
  • 不是实时协同编辑：不支持多人同时改同一份 HTML。
  • 不是公开填报工具：公开链接只读，写入需要登录或签名 Webhook。
  • 不是多租户 SaaS：单实例部署，公开链接靠 bearer token。
  • 不适合大数据量：单表 2 万行 / 5 MB，每个应用最多 12 张表。
↳简单说：它适合结构清楚、读多写少、需要分享出去的场景；不适合核心交易、复杂流程和大量并发写入。
能落表1–12 张表，字段稳定
读多写少导入 / 人工维护 / 事件写入
交付是表 / 链接不是复杂流程
不需要实时协同没有 CRDT / 多人改 HTML
小结先把场景选对，比急着加功能更重要。

10 Product / 事件与调度

用事件接收变化，用定时任务刷新数据

事件先写进数据库再投递，至少送达一次；应用级定时任务用数据库租约和心跳，保证多实例下只跑一次。

事件收件箱

收件箱 / 出站
  • 收件箱：事件写进 light_app_events，页面按游标读取并确认；默认保留 500 条、30 天。
  • 出站：所有者配置 Webhook 地址和事件类型，发送时带 HMAC 签名，复用 external outbox。
  • 入站：应用有自己的入站入口，支持 app.inbox、app.import 和 app.refresh。
  • 触发器：表规则可以在新建或更新行时写入收件箱。
  • 页面：页面用 events()、ackEvents()、emitEvent()，都受能力位限制。

应用级定时任务

数据库租约
  • light_app_schedules 支持 sync_source 和 snapshot_publication 两种任务。
  • 每 30 秒扫描一次，用条件 UPDATE 抢 lease_until，执行期间每 60 秒续租。
  • 失败后按间隔指数退避，最长 24 小时；成功后加一点随机抖动，避免同时重跑。
  • 数据源同步按批次内容幂等，超时或崩溃后重试不会重复写入。
  • 公开链接可以开启自动刷新快照，只有所有者和管理员能改。
App inbox游标 + ack · 500 条
External outbox租约 · 退避 · 死信
Webhook postHMAC · at-least-once
App ingress签名 · 限额 · 幂等
WS frame只加速 UI
↳不要另建 EventBus：应用事件复用现有事件平面，payload 不能决定投递目标、模式或表。
订单进入后触发审核入站 Webhook → app.inbox → 页面处理
每天同步sync_source 定时拉连接器或文件

小结事件负责告诉你发生了什么，定时任务负责什么时候刷新；两者都从数据库状态恢复。

2

14 Security / 安全模型

安全从身份、能力、审批、沙箱和审计一起做

MiniApp 里是 Agent 生成的数据和代码，默认按不可信内容处理。

身份 / ACL

登录用户、应用会话和访客分开；成员和访客按表、按行判断；宿主可以限制外部参与。

能力清单

页面能调用什么写在 capabilities_json 里，未知方法直接拒绝。

审批 / 风险分级

app_* 工具按读、写、敏感分级；删除、改结构、导入和集成写操作需要人工确认。

沙箱 / CSP

双层 iframe、default-src 'none'、WebRTC/frame 冻结、逃逸熔断。

审计 / 限流 / PII

管理动作和工具调用会记录指纹；公开 token 按 IP 限流；公开面统一脱敏。

公开链接是 bearer token令牌即凭证；只读；不因持有链接而获得平台身份。
页面过滤不是访问控制公开面只认 public_visible 和独立公开表。
IM 工具闸门app 数据工具要求所有者私聊；群聊或非所有者只能拿链接 / 打开入口。
↳工具审计：每次 app_* 调用会记录调用者、Agent、应用、风险等级、发送者和所有者标记、参数键、参数指纹、状态和耗时；不记录原始参数、PII 或密钥。
页面不能联网CSP connect-src 'none'；外链只走宿主
服务端再校验generate / game / service / events 都 require_capability
公开面不接受 JWTtoken 即凭证；只读；不能写 / 生成 / 游戏
小结每一层都假设上一层可能失效。

15 Scenarios / 高频场景

四个容易起步的场景

共同点是数据结构清楚、读多写少，最后交付一张表、一个看板或一个链接。

A. 台账与填报

形态：门店 / 巡检 / 客户跟进表，按人可见、状态流转。

能力：快速创建、row_scope=user、状态机规则、页面写行、行级历史。

边界：填报者可以是平台成员、协作者或受邀访客；匿名公开填报还没做。

最推荐起步1–5 天

B. 轻看板与摘要卡

形态：Excel → 看板 / 台账 / 进度板；公开链接；工作台格子。

能力：快速模式三视图、服务端聚合与图表、发布快照、Board / 桌面。

边界：公开看板还没做；快速模式的图表类型有限。

最直观演示手机可看

C. 外部数据速览

形态：豆瓣读书、公开 JSON / 文本、连接器数据。

能力：只读外部服务（工具白名单、URL 前缀、缓存和限流）。

边界：只读，不能写回外部系统；还没有 builtin 到 external 的 promote。

外部服务缓存

D. 审核与内容流转

形态：审片 / 质检 / 合规：列表 → 预览 → 通过 / 驳回 → 留痕。

能力：状态机、行级历史、页面写行、导出、ACL。

边界：页面不能上传文件，同源视频播放还没做；不能替代剪辑或工作流。

状态机行历史
推荐起步A 台账 → 1–5 天看到结果
最直观演示B Excel → 看板 → 手机链接
最需要治理D 审核：状态机 + 行历史 + PII
小结A 解决多人维护，B 让结果好看，C 接入外部数据，D 管状态和留痕。

把它当成结果页面，不要当成数据库

对外只读发布、给外部系统补最后一页、个人或团队的小工具，这三类最容易见效。

CRM、工单或订单数据同步过来，做成业务页面：入站 Webhook、出站 Webhook、定时同步和应用级调度。

ingressoutboundschedule

G. 个人 / 团队轻工具

番茄钟、报名表、资料目录或外部游戏：一个 HTML 文件加 SDK、能力清单和游戏 token。

轻量可分享

什么时候不适合

不适用
  • ERP / CRM 权威库、核心交易、强一致账务。
  • 公开填报、匿名写入、公开看板分享。
  • 复杂 BPM、任意工作流、实时协同编辑。
  • 超过 2 万行 / 5 MB 的高频数据面。

什么时候适合

适用
  • 数据能落成 1–12 张表，读多写少。
  • 交付物是台账、看板、进度板或只读页。
  • 需要快速改界面、改字段、改指标。
  • 结果需要分享给同事、客户、门店或大屏。
对外发布政策 / 价目 / 名单 / 结果页
数据落地CRM / 工单 / 订单 → 业务页面
轻工具番茄钟 / 报名 / 资料目录
小结如果它只是外部系统缺的一页，MiniApp 很合适；如果要替代核心系统，就不合适。
