13 Fit

先说清楚：谁适合，谁不适合

把边界说清楚，比多列十个功能更能建立信任。

适合

想在自己的环境里，把 AI 用进真实工作

  • 个人 / 家庭极客，想要一个长期助理
  • 10–200 人团队，想在 IM 里用专家与知识库
  • 有台账、报表、客户跟进需求的业务团队
  • 研发 / 运维团队，需要终端、浏览器与自动化
  • 金融、医疗、政企等需要私有化部署的组织

不适合

这些边界，最好在 POC 前就确认

  • 需要多租户 SaaS 集群、跨地域高可用
  • 需要分布式内核或外部大规模队列
  • 需要零配置的消费级 App
  • 需要复杂 BI、流程引擎或原生小程序运行时
  • 不能接受自己运维一台服务器 / 容器
数据能不能出内网？决定部署方式、模型选择和是否本地化。
团队多少人？决定个人电脑、团队服务器还是多实例。
最痛的一个流程是什么？决定第一个 POC 场景，而不是先买全平台。
↳单节点是部署选择，也是责任边界。每个团队 / 客户一个实例，数据不出节点；跨部门强隔离建议每部门 / 环境一个实例。

14 Get started

三种开始方式，选一个适合你的

个人先试用，团队上服务器，合规环境走私有化。

个人电脑 · 先试用

安装后本地启动，先做一个自己的助理；适合个人与家庭。

  • 数据在自己的电脑
  • 可以接 IM 与定时任务
  • 不满意随时备份迁移
一键安装pipPWA / 桌面

团队服务器 · 一起用

Docker Compose 或系统服务；开启 TLS、备份与多用户。

  • 多用户与权限
  • TLS / 备份 / 服务托管
  • 适合 10–200 人团队
Dockersystemd / launchd10–200 人

私有化环境 · 合规用

内网部署；PostgreSQL、SSO / LDAP、审计与本地模型。

  • 数据不出内网
  • 可接 SSO / LDAP
  • 本地模型与 embedding
内网PostgreSQLOllama
1 · 配一个模型选预设或 Ollama，测试连接后保存。
2 · 建一个专家从 24 个模板里选一个，填名字即可。
3 · 接一个入口先用 Web 或一个 IM 群，跑通第一件事。
pip install octop→octop init→octop run→http://127.0.0.1:8088
↳也可以使用一键安装脚本（无需预装 Python）、Docker、桌面客户端或 FnOS。除 LLM provider 外，无必需外部服务；首次启动有设置向导。
Takeaway不确定选哪个？先在个人电脑跑通一个场景，再搬到团队服务器。
