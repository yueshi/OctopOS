01 Product / 定位

不是另一个聊天机器人，而是可自托管的 AI 工作平台

把「对话」升级为「可交付的工作」：Agent 有工作区、有工具、有记忆，产出能被人直接使用。

OctopOS 的目标不是让 AI 更会聊天，而是让 Agent 在你的服务器上完成工作：查资料、写文件、跑流程、生成应用，并把结果交付给人。

For individuals

对个人

一个记得你、能动手的长期助理。聊天、记忆、定时任务、IM 入口，都在自己的机器上。

典型产出：日报、提醒、资料整理、自动化脚本。
长期记忆定时任务IM 直达
For teams

对团队

多用户、多专家、可编排的数字同事。共享知识、工作台、审批和决策账本。

典型产出：任务看板、评审记录、经营报表、客户回复。
专家库团队编排审批
For business

对企业

可私有化、可接业务系统、可交付 MiniApp。数据不离开自己的节点，权限与审计留在内部。

典型产出：业务台账、审批流、公开数据页、私有知识助手。
私有化OAuth / MCP审计
单节点 AgentOS每个团队 / 客户一个实例，部署与责任边界清晰
不是 SaaS 集群不做多租户进程隔离，不引入外部队列
MiniApp 是投影层承载人可用的界面，不是权威业务数据库
默认可信内网强隔离用 Docker 沙箱 / 账号与网络边界
TakeawayOctopOS 卖的是一块可交付的工作台，而不是一个更聪明的聊天窗口。

让工作自己发生：调度、事件与主动执行

定时任务负责「什么时候做」，外部事件负责「发生了什么」，两者都汇入同一个 Agent 运行时。

Cron · 定时任务

scheduler
  • 进程内 APScheduler，无外部 worker / 队列

  • 结果推送 Dashboard / IM；失败与超时可见
  • 聊天进行中可补一句 steering，不必等本轮结束

Events · 外部事件

inbox / outbox
  • Webhook（HMAC）+ connector poll（30 秒扫描）
  • external_events → external_deliveries → expert / team / app inbox / webhook
  • 去重、合并窗口、限流、指数退避、死信、30 天保留
  • at-least-once；消费方必须幂等
  • payload 不能决定 target / mode / table

15 Operations / 安全

默认最小暴露：认证、授权、审批、隔离、脱敏

安全不是单点开关，而是五层叠加；每一层都能单独验证，也都能在出问题时留下证据。

认证

  • JWT
  • 邀请码
  • OIDC SSO
  • LDAP

授权

  • 用户级 ACL
  • Agent 归属校验
  • 应用协作者
  • 管理员绕过审计

审批

  • HITL 工具审批
  • app_delete 强制
  • Shell guard
  • 频道内审批

隔离

  • MiniApp 沙箱 iframe
  • 无 JWT / 无网络
  • Docker 沙箱可选
  • 按 Agent 工作区

数据

  • PII 检测 / 脱敏
  • secrets 加密
  • audit_log
  • 备份 / 恢复

MiniApp 的双层沙箱

页面在无 JWT、无网络的 iframe 中运行；所有 I/O 经宿主 bridge，按能力清单裁剪。公开链接只读，PII 统一脱敏，发布快照冻结 HTML 与表结构。

部署边界要诚实

默认是可信内网的单节点，Agent 工作区默认 host-rooted；插件是进程内 Python，与 MiniApp 是两套信任模型。生产建议 Docker / 独立账号 + TLS + 最小权限。

↳审计现状：管理动作已进 audit_log；工具级「谁 → 何时 → 什么权限 → 调了什么 → 结果」将随能力合约补齐。
Takeaway安全的目标不是零信任一切，而是让每次越界都可解释、可阻断、可追责。

17 Roadmap / 边界

能承诺什么，不能承诺什么

把边界说清楚，比多列十个功能更能建立信任。单节点是部署选择，也是责任边界。

现在可以承诺

已交付、可验证、可演示

  • 单节点多用户、多 Agent；JWT + 资源 ACL
  • 10 类 IM + Web + CLI + API 共享同一运行时
  • MiniApp 数据 / 界面 / 发布 / 备份 / 权限
  • 31 个连接器 + MCP + 外部事件 + Cron
  • 自托管运维全套：TLS / 备份 / 服务 / 升级

不要过度承诺

能力边界与责任边界

  • 不是多租户 SaaS 集群；每客户 / 团队一个实例
  • 不是分布式内核；跨节点用 Bridge 或外部协调层
  • MiniApp 不是权威业务库，单表 2 万行上限
  • 团队自治是 bounded agentic，L3 仍在推进
  • 默认 host workspace；强隔离需 Docker / 账号边界
Roadmap执行隔离 / 配额能力合约 / 三态策略统一调度 / 租约预算 / 计费可观测 / 成本归因MiniApp 包版本化 / 市场
要私有化？每团队 / 客户一个实例，数据不出节点。
要多入口？IM + Web + CLI + API 共享同一运行时。
要交付应用？Agent 产出可直接变成 MiniApp 与公开链接。
单节点不是限制，是部署与责任边界：一个团队 / 客户一个实例，数据不出节点。
