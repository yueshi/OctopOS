# 装修设计校验阈值校准清单

> 版本：2026-11-27　对应提交：`ffbe8435` 之后
> 代码位置：`src/octop/infra/design/catalog.py`（品类尺寸与逐类净空）、`src/octop/infra/design/checks.py`（全局阈值）
> 回归基线：`tests/unit/design/fixtures/`（两套真实户型）、`tests/unit/design/test_thresholds.py`（逐键覆盖）

这份清单给**装修领域顾问**逐条确认：每个阈值现在的默认值、依据是什么、为什么值得复核。确认结果直接写成方案里的一条 `setting` 行，**不需要改代码**。

---

## 0. 怎么用

1. 每张表最后一列是「建议值」——**留空表示认可默认**，需要改就填数字。
2. 拿不准的项，看「为什么需要确认」一列；仍有疑问的，记在第 8 节。
3. 改值方式（写在方案的 `main` 表一行里）：

```json
{
  "element_id": "S-001",
  "kind": "setting",
  "name": "项目口径",
  "payload": "{\"thresholds\":{\"route.width_mm\":800,\"front_clearance.fridge\":1000}}",
  "source": "业主/地区要求",
  "status": "confirmed"
}
```

4. 改完跑一次回归，确认影响范围：

```bash
uv run pytest tests/unit/design -q
```

默认值下两套真实户型的诊断与算量是冻结的（`test_plan_fixtures.py`）；如果改了**默认值**而不是项目覆盖，快照会变红，这是有意的提醒。

## 1. 优先复核的 8 项（影响最大）

| # | 键 | 默认 | 影响 | 为什么需要确认 |
|---|---|---|---|---|
| 1 | `route.width_mm` | 600mm | 判定整份方案「是否可达」（blocking） | 600 是行动自如的最低值；老人、无障碍、有婴儿车/轮椅的家庭通常要 800–900。这个值最容易因客群而变 |
| 2 | `front_clearance.fridge` | 900mm | 冰箱能否开门取物 | 对开门冰箱、法式冰箱要求更大（1000–1200）；900 是按普通双门冰箱 |
| 3 | `front_clearance.kitchen_counter` / `sink` / `stove` | 900mm | 厨房操作通道 | 单排厨房 900 尚可，双排/岛台通常要 1000–1200 |
| 4 | `clearance.storage_front_mm` + 衣柜/储物柜 | 700mm | 柜门能否打开、能否蹲取 | 平开门 700、推拉门可到 500–600；老人使用建议 800+ |
| 5 | `clearance.sanitary_front_mm`（马桶/洗手盆/淋浴/浴缸） | 600mm | 洁具前能否使用 | 马桶前 600 是底线；无障碍马桶前侧需要 750–800 |
| 6 | `safety.splash_zone_mm` | 600mm | 湿区插座是否判不合规（blocking） | 与当地电气规范（如淋浴区 0/1/2 区划分）直接相关，**应以当地规范为准** |
| 7 | `programme.min_area.<kind>` | 客厅 12 / 卧室 9 / 厨房 5 / 卫生间 3 / 阳台 1.5 ㎡ | 房间是否被判过小 | 与地区住宅设计标准相关（例如部分城市对卧室有下限） |
| 8 | `room.occupancy_min` / `room.occupancy_max` | 10% / 40% | 房间是否被判过空/过挤 | 40% 对小户型偏紧；10% 对卧室偏松。建议按房型分档 |

## 4. 安全、施工与人体工学

| 键 | 默认 | 依据 | 建议值 |
|---|---|---|---|
| `safety.splash_zone_mm` | 600 | 湿区溅水半径（**应以当地电气规范为准**） | |
| `ergonomics.seat_table_delta_min` | 250 | 座面到桌面的最小高差 | |
| `ergonomics.seat_table_delta_max` | 320 | 最大高差 | |
| `ergonomics.seat_table_reach_mm` | 1200 | 只配对这个距离内的餐桌/书桌 | |
| `assembly.tall_item_mm` | 1800 | 超过此高度要检查能否在层高下立起 | |

**不可调但需知晓的判定**：
- 固定设备（冰箱/灶具/洗碗机/洗衣机/马桶/洗手盆/浴缸/台面）必须贴墙——「贴墙」的容差是墙厚；
- 门扇 90° 开启扫掠内不得有家具（blocking）；
- 入户视线：从入户门沿进门方向、被第一道实墙截断之前，不得直视床或马桶；
- 高柜立起判定用 √(短边² + 高²) ≤ 层高。

## 8. 需要顾问拍板的问题

- [ ] 通道 600 是否要按客群分档（年轻人 600 / 老人 800 / 无障碍 900）？
- [ ] 冰箱前净空按门型区分（单门 900 / 对开 1100 / 法式 1200）？
- [ ] 厨房双排/岛台的通道是否统一 1000+？
- [ ] 卫生间是否要区分干区/湿区、马桶前侧向空间（侧向 200 是否要加规则）？
- [ ] 溅水半径以哪一版规范为准（请给出条款号）？
- [ ] 房间最小面积是否按本地住宅设计标准调整？
- [ ] 家具占用率 40% 上限是否对小户型放宽（如 45%）？
- [ ] 座面–桌面 250–320 是否覆盖常见餐桌（720–760）与椅面（420–460）？
- [ ] 给排水点位 1500mm 服务半径的工程口径是多少？
- [ ] 高柜“立起”判定是否要考虑电梯/楼道搬运（目前只判房间内）？

## 9. 回填后怎么验证

1. 把确认结果写成 `setting` 行（见第 0 节）。
2. 跑 `uv run pytest tests/unit/design -q`：
   - 用**项目覆盖**时，两套 fixture 的默认快照不应变化；
   - 如果确认结果要改**默认值**，请同时更新 fixture 快照并在提交说明里写清依据。
3. 需要逐条验证某个键，参考 `tests/unit/design/test_thresholds.py`：每个键都有一个“默认失败 → 改值通过”的用例。
